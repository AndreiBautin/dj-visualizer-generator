# Testing

## One gate

Install locked frontend packages with `npm ci --prefix frontend`, then run `npm run verify` at the repository root. Node 24, .NET 9 SDK, FFmpeg and ffprobe must be on PATH. Install the pre-push hook with `npm run prepare`.

The gate runs project-boundary checks, guardrail regression tests, frontend lint, .NET/Prettier format checks, strict backend build, backend tests, frontend tests, and both default and standalone typed frontend builds. It requires five backend TRX reports and rejects skipped tests. The media availability probe drains process output and has a bounded timeout; an unavailable dependency must not silently approve a release.

## What the tests protect

- Domain: validation and legal job transitions.
- Application: orchestration and failure handling using ports.
- Infrastructure: real file persistence, upload signatures, rendering arguments, real FFmpeg output, egress arithmetic, and exclusive instance leases.
- API: binding, safe errors, sample configuration, range responses, preview budget enforcement and concurrent download admission. Ten simultaneous download requests must admit exactly five.
- Frontend: file/settings validation, progress/recovery states, sample submission, previews and accessible controls. An expired job offers recovery instead of endless polling.
- Browser: synthetic upload through real rendering and download. Run `E2E_BASE_URL=http://localhost:5080 npm --prefix frontend run test:e2e` against standalone mode, or the default 5173 compose stack. Playwright's Chromium must be installed.
- Accessibility: axe audits the form in both colour schemes and the finished screen after a real render (`e2e/`), so a contrast regression fails CI's browser job.
- Visual: `npm --prefix frontend run test:visual` screenshots the form, rendering, finished and failed screens in both themes against a mocked API. Baselines live in `frontend/visual/__screenshots__/<platform>/`; after an intended change, review the diff and rerun with `-- --update-snapshots`.
- Release: Docker image smoke checks and a live expected-commit check that downloads and decodes a sample MP4.

Current totals and actual run results are recorded in PORTFOLIO_DEMO_READINESS.md. Historical counts are not a substitute for executing the gate.

## Manual Safari checklist

Playwright's WebKit is the automated stand-in; real Safari (macOS and iOS) differs in media and transitions. Until it is checked on hardware, run this by hand after UI changes:

1. Form loads with the record spinning; light and dark both follow the system setting.
2. Pick a WAV and an MP3: the waveform appears, Play preview plays, and long files show "first m:ss".
3. Pick wide artwork: Left/Centre/Right move the label; drag and arrow keys move it too.
4. Generate: the screen cross-fades to progress (or switches instantly with Reduce Motion on), and the tab title shows the percentage.
5. Finished: the poster shows, the video plays and seeks, Download saves an `.mp4` (not `.html`), and the badge drops to 4 saves left.
6. Reload the job URL: it returns to the finished job without replaying the burst. Copy link pastes the same URL.
7. iOS only: Add to Home Screen, open it offline, and see the offline banner with Generate disabled.

## Deliberately not tested

Pixel-perfect FFmpeg snapshots are brittle across encoder/platform builds; inspect a real output visually. Timing is recorded as a measurement, not a pass/fail assertion on shared hardware. Multiple workers are unsupported and rejected by a lease; a distributed queue is outside this product. Hosted load/cost limits need separate measurements on actual hardware. We test our integration with FFmpeg and ASP.NET, not their internal implementations. The visual suite is not a gate. Font rasterisation differs between Windows and Linux, so baselines are kept per platform; CI's `visual` job compares against the Linux set and reports differences as a warning with the screenshots attached, never a failed check, because Render deploys only after checks pass and antialiasing must not block a release.

## Helpers

`JobsApiFactory` isolates test storage and substitutes duration probing for API tests. `SilentWavBuilder` synthesizes media. RequiresFfmpeg attributes support focused developer tests, but the full gate rejects their skips. Public fixtures are generated by `scripts/generate-demo-assets.sh`.
